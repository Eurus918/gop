# 🐣 随行 GoP

> 面向 **P 人**（临时起意型旅客）的分钟级出行规划助手。
> 一句话说出目的地，它给你：可执行的车票、酒店、精确到分钟的路线，以及网友真实踩过的坑。

---

## 它到底解决什么

现有旅行产品给你的是**信息**：攻略、列表、评分、一堆链接。
但你真正缺的是**决策**：明天到底几点出门？赶不赶得上？这个景点值不值得为它牺牲两个小时？

GoP 的输出不是攻略，是一条**能照着走的时间轴**。每个时刻都是算出来的——
算的依据是景区的停止入园时间、末班车、你的发车时刻，以及两点之间的真实车程。

**最关键的一点：改任意一个参数，全链路自动重排。**
攻略改一个字你得自己重算全程；这里改一个点，引擎替你算，冲突的地方标红。

## 30 秒跑起来

**零依赖**，不需要 `npm install`。

```bash
git clone https://github.com/Eurus918/gop.git
cd gop
node server/index.js
# 打开 http://localhost:3000
```

开箱即用，**车次默认就是真实实时的**——不需要配任何 Key。

想更进一步：

```bash
cp .env.example .env
# 填入 AMAP_KEY（免费申请：https://console.amap.com/dev/key/app）
node server/index.js
```

配了 `AMAP_KEY` 之后：路径规划、天气、以及**任意城市的景点动态生成**都会切到真实数据。
不配的话，路径用车程矩阵估算，城市只支持人工维护的景点库（当前：珲春）。

## 核心能力

### 1. 分钟级排程引擎 `server/planner.js`

这是整个项目唯一真正有壁垒的部分。

它做的事：

1. **先定返程班次，再倒推游玩截止线**——反过来的话会出现"景点早早排完、下午干等两小时"
2. **片区聚类 + 优先级贪心**排景点——纯按优先级会导致"防川 → 沿线 → 再回防川"来回跑
3. **硬约束校验**：到达晚于停止入园 → 砍掉；剩余时间不够 → 砍掉；超过闭园 → 砍掉
4. **景观重复组去重**：金沙滩和沙丘公园同类，只留一个
5. **赶车倒推链**：`发车 ← 安检 ← 酒店到站 ← 取行李 ← 游玩结束`，得出"最晚几点必须走"

实测输出（延吉 → 珲春，2 天 1 晚）：

```
08:45  C1003 延吉西 → 珲春
09:25  抵达 → 酒店寄存行李
...
14:07  回到市区 · 打车去酒店        ← 关键节点
15:35  取行李 + 结算退房            ← 关键节点
16:00  ★ 从酒店出发去车站           ← 关键节点
16:30  到站 · 安检进站              ← 关键节点
16:50  C1040 珲春 → 延吉西
```

把返程改成 18:46 的 C1026，整条链自动重排成 17:31 取行李 / 17:56 出发，
并且因为时间变宽裕，**多排进了原本被砍掉的景点**。

### 2. 景点库 `server/data/pois.js`

每个景点不是一张名片，而是**一组可被算法使用的约束 + 一条取舍建议**：

```js
{
  id: 'longhuge',
  name: '龙虎阁（一眼望三国）',
  durationMin: 60, priority: 10,
  hours: { open: '08:00', close: '17:00', lastEntry: '16:00', lastShuttle: '16:30' },
  bestWindow: ['08:30', '11:00'],   // 午后起雾就白来了
  skipIf: ['雾', '大雨'],
  dupeGroup: 'sand',                 // 同类景观只排一个
  gear: ['望远镜'],                  // 会进准备清单
  pitfalls: [{ score: '携程 3.4 分', quote: '…只是到三个国家交界的一次打卡', advice: '…' }]
}
```

### 3. 可插拔数据源 `server/providers/`

| Provider | 状态 | 说明 |
|---|---|---|
| `train12306.js` | **默认启用** | 12306 官方公开查询接口：**真实余票 + 真实票价**，任意站点对，内置全量站点码表与限速缓存 |
| `amap.js` | 需 key | 高德：地理编码、驾车/公交路径规划、天气、POI。**决定了分钟级排程的车程可信度** |
| `llm.js` | 需 key | OpenAI 兼容协议，DeepSeek / 通义 / Kimi 都能直接填。行程数据注入上下文（轻量 RAG） |
| `mock.js` | 兜底 | 真实采集快照；上面任何一个挂了都会静默降级到这里 |

**任何一个数据源失败都会静默降级**，并在返回里标注 `degraded` 和原因，不会白屏。

### 车次为什么能是真的

12306 没有「开放 API」，但它的**官方网页自己在用公开查询端点**（无需登录即可查余票与票价）。
本项目调的就是这个端点，返回的是真实数据：

```
去程: C1003 08:45→09:25  二等 ¥28  一等 ¥45  余票 有
返程: C1026 18:46→19:26  二等 ¥28  一等 ¥36  余票 有
数据源: 12306
```

支持任意站点对（成都东→重庆北 实测 161 班车），站点名不必精确——
输入「延吉」也能自动匹配到「延吉西」。

> ⚠️ **请遵守**：这是公开查询端点而非官方开放 API，稳定性无承诺。
> 项目内置了最小请求间隔 1.2s 与结果缓存，**仅限个人低频使用**，不要用于高频或商业调用。
> 商用请走官方授权渠道。不想联网可在 `.env` 设 `TRAIN_PROVIDER=snapshot`。

### 4. AI 小助手

- 配了 `LLM_API_KEY` → 走大模型，行程数据作为上下文注入，回答的是"你这趟"而不是旅游常识
- 没配 → 本地规则引擎，命中内置知识库；**命中不了就老实说不知道，绝不编造**

## 关于数据，必须说清楚的两件事

**一、车次是真的，酒店房价不是。**

车次已接 12306 官方公开查询接口，余票、票价、历时全部实时（见上）。

但**酒店实时房价必须拿到 OTA 商务授权**才有，这是目前唯一拿不到实时数据的模块——
当前用的是真实采集的快照（含采集日期），页面会明确标注为参考价，不伪装成实时。
你有合规数据源的话，在 `.env` 里配 `HOTEL_API_BASE` 即可接入（约定格式见 `.env.example`）。

同理，景点门票的实时库存也需要美团/携程的商务对接，目前只给官方购票跳转。

**二、网友评价是观点，不是事实。**
避坑模块里的评分和吐槽都标注了出处（携程景点评分 / 公开游记原文）。
它们会过时，也会有人不同意——欢迎提 PR 校正。

## 项目结构

```
gop/
├── server/
│   ├── index.js            HTTP 服务 + 静态托管（零依赖）
│   ├── config.js           配置中心，密钥只从环境变量读
│   ├── planner.js          ★ 分钟级排程引擎
│   ├── providers/
│   │   ├── index.js        统一出口 + 失败降级
│   │   ├── train12306.js   ★ 12306 实时余票与票价（默认启用）
│   │   ├── amap.js         高德：路径规划 / 天气 / POI（需 key）
│   │   ├── llm.js          大模型 + 本地规则引擎
│   │   └── mock.js         真实采集快照（兜底）
│   └── data/
│       ├── pois.js         ★ 景点库（硬约束 + 取舍建议）
│       └── sample.js       车次 / 酒店 / 问答快照
├── public/                 前端（原生 JS，无构建步骤）
├── test/run.js             排程引擎测试（node test/run.js）
└── .env.example
```

## 想加一个城市？

往 `server/data/pois.js` 的 `CITIES` 里加一条就行，排程引擎、清单生成、避坑模块会自动接上。
需要给的是：景点开放时间 / 停止入园 / 片区之间的车程矩阵 / 城市硬规则 / 网友吐槽。
